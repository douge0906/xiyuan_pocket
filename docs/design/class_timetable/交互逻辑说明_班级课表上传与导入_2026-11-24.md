## 0. 全局交互约定

| 约定 | 说明 |
|---|---|
| **术语** | 「班级」= 四段归属定位的一个班；「课表」= 一份上传记录（含 N 门课程）；「版本」= 同一上传者对同一班级的第 N 次提交；「上传者名称」= 用户自填的展示名（≤16 字） |
| **加载态** | 列表用骨架屏（不用转圈遮罩），详情用居中 `CircularProgressIndicator(strokeWidth: 2.5)` |
| **错误态** | 列表页：顶部错误条 + 保留上次结果 + 「重试」；详情页：整页错误态（`ErrorState`）+ 「重试」 |
| **提示方式** | 操作结果用 SnackBar（floating、距底 24、2 秒、圆角 radiusMd）；状态变更用「标题 + 详情」两行式 |
| **破坏性操作** | 撤销上传、删除本地课表、**覆盖本机课表** → 二次确认弹窗；审核「下架」→ 二次确认 |
| **网络失败** | 所有写操作失败时，**本地草稿不丢**，返回上一步仍保留已填内容 |
| **离线** | 检索结果走本地缓存（30 分钟），无网时显示缓存 + 顶部「当前为离线缓存」提示条 |
| **覆盖语义（关键）** | 导入锡院在线课表 = **直接覆盖**本机同名班级课表（仅限 `kindImported`），覆盖前必须展示差异明细；**不逐条合并** |
| **数据源单一** | 检索页**只有一个数据源**（已审核发布的锡院在线课表库），没有「社区 / 我的教务」分段切换 |

**导航层级约定**

- 班级课表检索页、详情页、上传向导、我的上传页、「导入课表」面板都是**二级页面 / 弹层**，从课表 tab 或服务 tab 进入，**不显示底部导航**（现行安卓 `IndexedStack` 的 5 个一级页面才带底部导航）。
- 底部导航只在一级 tab 出现，规格按 `lib/app.dart:603-771`：高 56、白底、上方阴影 `0 6% 黑 blur 20 offset(0,-4)`、选中项圆角 16 指示块底色 `primary 8%`（深色 14%）、24px 图标、11px 文字（选中 600 主色 / 未选 `#9CA3AF`）。
- **没有中间圆形 FAB**：该浮钮只存在于 v1.0.2 / v1.0.3，`d83f01b`（v1.0.4）起已移除；现行分支是「圆角指示块 + 5 个平铺图标」，设计稿按现行画。

## 1. 主流程总览

```
课表页 ──右上角「导入」按钮──「导入课表」面板──┐
                                                  │ 面板行卡（第 7 行）：
服务 tab ─────────────────────────────────────────┼─ 锡院在线课表 ← 本次新增
                                                  │   （点击后关闭面板，直接进检索页）
                                                  │
                        锡院在线课表 → 检索页（搜索栏置顶 + 可改学年学期）
                                          │
                        检索班级 → 详情页（三段式）
                        ① 班级基础信息
                        ② 班级课表（多版本等宽卡：课程数/上传时间/上传者）
                        ③ 课程预览（跟随选中版本实时切换）
                                          │
                        导入确认 sheet（覆盖提示 + 差异明细）
                                          │
                        覆盖或新增本机同名班级课表（整表替换）
                        → CourseStorage 落库 → 切表 → 课表页生效
                                          │
                        ┌─────────────────┘
                        │ 空态
                        ▼
                「上传班级课表」→ 上传向导 3 步
                  Step1 归属四段 + 来源两选一（本机课表 / 本机文件）
                  Step2 课程核对（编辑/补全）
                  Step3 提交确认 + 上传者名称 + 隐私自检
                        │
                POST /timetables/uploads → status=pending
                        │
                「我的上传」页跟踪 → 审核员处理
                        │
        ┌───────────────┴───────────────┐
    approved                        rejected
        │                                 │
  发布队列（outbox）           驳回原因 + 意见 → 修改后 resubmit
        │                                 │
  客户端可检索                        升版本 v(n+1) → 回到 pending
```

**两个覆盖语义并存，别混**：

| 场景 | 动作 | 说明 |
|---|---|---|
| 用户**上传**同一班的第二份 | 服务端**并存**（同上传者同来源升版本；不同上传者并列） | 在线课表要保留多份，因为上传者不同，可能各有对错 |
| 用户**导入**别人的课表到本机 | 客户端**覆盖**本机同名班级课表 | 本机只需一份可用版本，用户要的是「现在就用这份」 |

即：**在线课表多份并存，本机一份覆盖。**

## 2. 检索页（App · 锡院在线课表）

### 2.1 首屏结构（无分段控件）

从上到下，**没有多余的分段切换**：

```
┌ ‹        锡院在线课表        ⋯ ┐   ← AppBar 标题即入口名
├────────────────────────────────┤
│ 🔍 搜班名 / 专业 / 学院，例如：25安工 │  ← 搜索栏置顶
├────────────────────────────────┤
│ (2026-2027 第1学期 ▾)  学院  专业  班级 │  ← 学年学期 chip 可改，其余三级筛选
├────────────────────────────────┤
│ 共 128 个班级        已审核发布 214 份课表 │
└────────────────────────────────┘
```

- **去掉了分段控件**：原先的「社区课表库 / 我的教务（实时）」两个 tab 被移除，首屏直接是搜索栏。理由：分段让首屏多一层无信息量的切换、挤掉搜索栏位置，而且「谁的课表」与「别人传的课表」混在一屏会让人分不清可信度。
- **教务实时路径没有删除**：它仍存在于「课表页 → 导入课表面板 → 从教务系统导入」与「导入一份新课表 → 输入账密快速导入」这两条老路上，只是不再作为检索页的并列数据源。
- 顶部计数行：「共 128 个班级」+「已审核发布 214 份课表」，让用户知道库里有多大。

### 2.2 学年学期可更改

- 学年学期是**第一个 chip，且带虚线边框 + 下箭头**，视觉上就提示「这个可以改」。
- 点击 → 从底部升起学期选择 sheet（滚轮或列表均可），选项按 `_semesterOptions` 口径（`xnm` 如 2026，`xqm` 3/12/16）。
- 切换学期后：检索结果、班级计数、课表版本**全部按新学期重新加载**；已选 chip 文案更新为新学期。
- 若该学期**一个课表都没有** → 空态文案切到该学期口径（「该学期还没有同学上传过课表」）。

### 2.3 三级筛选（学院 / 专业 / 班级）

```
学院 ▸ 专业 ▸ 班级
```

- 三个 chip 常驻，未选时显示「全部」。
- 点击任一 chip → 从底部升起筛选 sheet（不逐级跳页，减少跳出成本）。
- sheet 结构：顶部一行四段联动选择器（学年 → 学院 → 专业 → 班级，可横向滑动切换当前段）→ 下方是当前段的**单选列表** + 班级数 + 底部「重置」「确定」。
- **联动规则**：
  - 选「学院」→ 专业列表刷新为该学院下的专业，班级列表清空。
  - 选「专业」→ 班级列表刷新为该专业下的班级。
  - **修改上级 → 下级自动清空**（不保留无效的旧组合，照抄 `class_picker_page` 的 `_grades` / `_colleges` 去重排序思路）。
  - 选到「班级」后自动关闭 sheet 并触发检索。
- 候选集只含「**已有人上传过课表**」的学院 / 专业 / 班级；未上传过的班级不进列表，只能靠搜索或「上传班级课表」补齐。
- 「重置」→ 清空四段 + 关键字，回到全量列表。

### 2.4 关键字检索

- 输入即时过滤（防抖 300ms），**不发请求**（与既有 `class_picker_page` 的本地过滤一致）。
- 匹配范围：班名 / 专业 / 学院 三字段，小写包含。
- 输入框有 `✕` 清除按钮；提示语沿用「搜班名 / 专业 / 学院，例如：25安工」。

### 2.5 结果卡片 → 详情

```
25电气1班                                    [32 人]  ›
电气工程及其自动化 · 智能工程学院
[2 份课表] · 28 门 · 一致 26/28 · 2 小时前
```

- 点击卡片 → 进入该班级详情页（**带筛选上下文**：学年学期 + 班级）。
- 卡片上的「N 份课表」标签是绿底 —— 这是「一个班有多份课表」的一级信号；点击标签等同点击卡片（不单独跳）。
- 一致度标签：`全一致`（绿）/ `26/28`（橙）/ 无基准数据（灰，标「未比对」）。
- 卡片只给**最新一份**的统计口径；具体多份的差异在详情页里比。

### 2.6 空态闭环

| 场景 | 文案 | 动作 |
|---|---|---|
| 关键字无结果 | 「没有找到匹配「25电」的班级」 | 主：清空关键字；次：重置筛选 |
| 筛选无结果 | 「该筛选条件下还没有课表」 | 主：上传班级课表；次：重置筛选 |
| 班级存在但无人上传 | 「该班还没有同学上传过课表。你可以先上传一份，审核通过后同学就能查到。」 | 主：上传班级课表；次：重置筛选 |
| 无网络 | 「无法连接课表服务：可能无网络」 | 主：重试；次：查看离线缓存 |

空态里始终有一句：**「你也可以上传本班的课表，审核通过后同学们就能检索到。」** —— 这是这条链路的自增长入口，也是「没有课表 → 谁来提供」的死结的解法。

## 3. 详情页（App）

### 3.1 结构（三段，自上而下）

```
① 班级基础信息     ← 白卡，四行键值对
② 班级课表         ← 多版本，等宽卡
③ 课程预览         ← 跟随 ② 实时切换
```

- 顶部 AppBar 标题为班级名，返回回检索页（保留筛选与滚动位置）。
- 底部操作栏常驻：`收藏`（次要）+ `导入到我的课表`（主按钮，实心）。

#### ① 班级基础信息

```
学年学期   2026-2027 第1学期
学院       智能工程学院
专业       电气工程及其自动化
班级       25电气1班
```

- 键列 66px 灰字（沿用 `.kv .k`），值列 13.5px 半粗（沿用 `.kv .v`），行间 1px 分隔线。

#### ② 班级课表（多版本）

```
班级课表                                    2 份
┌────────────────────┐ ┌────────────────────┐
│ v2        预览中    │ │ v1                 │
│ 28 门课              │ │ 27 门课            │
│ 2 小时前             │ │ 2 天前             │
│ 张同学               │ │ 李同学             │
└────────────────────┘ └────────────────────┘
```

- **等宽排列**（两列 grid，等宽等高，超出文字省略号，不换行撑高）。
- 卡面**只有三行小字**：课程数 / 上传时间 / 上传者 —— 别的信息一律不进卡面，避免卡片信息过载。
  - 课程数 = `28 门课`
  - 上传时间 = 相对时间（`2 小时前`）
  - 上传者 = 用户自填的名称（`张同学`）
- 版本号 `v2` 在卡头（选中态用主色），状态角标 `预览中` / `已发布`。
- **来源不占卡面**（在详情与后台可见），取值只有两种：`从本机课程表导入` / `从本机导出的文件导入`。
- 选中态：主色 8% 底 + 主色描边（照抄 `course_table_home_page` 的 `_conflictOption` 选中视觉）；未选中：白底 + 6% 黑贴边微影。
- 版本卡按**提交时间倒序**排列，最新在最前。

#### ③ 课程预览

- 标题 `课程预览 v2 · 28 门`，**随选中版本实时切换**（不重新进页面、不发请求）。
- 按星期分组（周一 ~ 周日），每门课一行：彩色左边条（`coursePalette` 浅色）+ 课程名 + `第N-M节` + `教师` + `@教室` + `周次`。
- **周次表达**：`1-16周`、`1-8周,10-16周`（复用 `parseWeeks` / `formatWeeks` 的能力，不新造格式）。

### 3.2 版本选择与收藏

- 点击任一版本卡 = **切换预览**（下方课程预览立刻换成该份的内容），**不立即导入**。
- 预览切换是**纯前端状态**，不发请求；点底部「导入到我的课表」才落库。
- 当前预览的那份标「预览中」（主色 8% 底 + 主色描边）。
- **多份都展示，不折叠、不隐藏**。不设「唯一正确版」，只按一致度排序。
- **收藏**：底部次按钮「收藏」。点击 → 变为「已收藏」（实心 + 勾）。收藏的是**班级引用**（`class_key`），不是课表副本；下次进详情页仍显示最新的一份。收藏列表在「我的上传」页并列展示。收藏失败不阻断浏览，仅按钮回滚 + SnackBar「收藏失败，请稍后重试」。

### 3.3 导入确认 sheet（导入链路的关键一屏）

点「导入到我的课表」→ 从底部升起 sheet（拖拽可下拉关闭）：

```
导入到我的课表
┌────────────────────────────────────┐
│ 课表名称   [25电气1班           ] │  ← 可改
│ 学年学期   [2026-2027 第1学期   ▼] │  ← 可改
├────────────────────────────────────┤
│ ⚠ 将覆盖你已有的「25电气1班」课表。 │
│ 新增课程   2 门   大学物理实验Ⅱ、模拟电子技术 │
│ 变更课程   1 门   数字电子技术（第9-10节 → 第7-8节） │
│ 移除课程   1 门   形势与政策            │
│ ℹ 本地该班课表会被替换。其他班级和    │
│   其他学期的课表不受影响。            │
├────────────────────────────────────┤
│ [        覆盖并导入        ]         │
└────────────────────────────────────┘
```

**确认逻辑：**
1. 名称默认 `<班名>`，可改；学年学期默认该课表的学年学期，可改（改了要提示「该课表的周次范围可能不适用」）。
2. **覆盖提示（橙）** 只在本机已存在同名班级课表时出现；本机没有时改为「将新增一份「25电气1班」课表」，不显示覆盖段。
3. **差异明细三行**（新增 / 变更 / 移除）只做**告知**，不做**询问** —— 不逐条合并、不让用户挑着导入。
4. **结果提示（灰）** 说明替换范围有限：只影响本班本学期这一份。
5. 点主按钮 → 按钮进入 loading（「正在导入…」），禁用重复点击 → 落库 → 关闭 sheet → 跳转课表页并自动切到该课表 + SnackBar「已覆盖「25电气1班」课表」。

**覆盖的边界（客户端必须守住）**：
- 只覆盖 `kindImported` 且归属四段（学年/学院/专业/班级）完全一致的表。
- **用户自己的 `kindOwn` 课表永远不被覆盖** —— 那是「我的教务」同步来的权威数据。
- 覆盖是**整表替换**，不逐条合并；覆盖后同步 `semesterStart`；不触碰其它班级 / 学期 / 课表外观。

**导入失败的兜底**：不关 sheet，按钮恢复，文案变「导入失败，请重试」+ SnackBar「导入失败：网络异常，请稍后重试」。

## 4. 上传向导（App，3 步）

向导是**单页 + 步骤切换**（不是三页跳转），顶部步骤条 `1 归属与来源 — 2 课程核对 — 3 提交确认`，已完成步骤可点回修改。

### 4.1 Step 1 · 归属与来源

**归属四段（全部必填，带红星）：**

| 段 | 控件 | 交互 |
|---|---|---|
| 学年学期 | 滚轮选择器 | 复用 `showSemesterPicker`；默认当前学期 |
| 学院 | 可搜索下拉 | 候选 = 在线课表库已出现的学院 + 本地缓存的学院；支持手输新名称 |
| 专业 | 可搜索下拉 | 候选随学院联动；支持手输 |
| 班级 | 「选择或输入班名」 | 优先从库中已知班级里选；也可直接手输（老师通知的班名常与系统不一致） |

- 任一段为空时点「下一步」→ 该行红星变红 + 行下方红字「请选择学院」+ 轻微抖动，**不跳步**。
- 班级手输时，给一行小字提示「输入的班级名会按「学院 + 专业 + 班名」归类，审核时会与教务基准核对」。

**来源两选一（整宽行卡，右侧 radio）：**

| 来源 | 副文案 | 取数路径 |
|---|---|---|
| **从本机课程表导入** | 读取你本机课表页里已有的那份课表 | 读 `CourseStorage.activeTable()` 的 courses |
| **从本机导出的文件导入** | 读取你导出的课表文件（`xiyuan.course.tables` JSON） | 解析 `course_transfer_service` 导出的文件，多表时选一张 |

- **只有这两种来源**：没有「我的教务导出」「上传 PDF」「拍照 OCR」这类入口。这正是审核成本可控的前提 —— 两种来源都是**本机已经存在的真实课表**，可信度一致，审核只需比对结构与一致度。
- 选中行卡时，副文案下方追加一行小字：「上传的必须是你本机已有的课表，审核通常 1 个工作日内完成。」
- 选「从本机导出的文件导入」→ 唤起文件选择（只接受本应用导出的 `.json`），格式不符 → 提示「这不是掌上锡院导出的课表文件」。

### 4.2 Step 2 · 课程核对

**解析结果顶部**：
- 全绿：「已识别 28 门课程，无异常」；
- 有问题（橙底 alert）：「已解析 28 门课程，2 处需要你确认」。

**课程清单**（按星期分组，组头「周一 · 4 门」）：
每行 = 彩色左边条 + 课程名 + `3-4节 10:10` + 教师 + `@教室` + 周次。

**问题课程标记**（橙色描边 + 行尾角标）：

| 角标 | 触发条件 | 处理 |
|---|---|---|
| 周次待确认 | 周次为空 / 解析异常 | 点行 → 编辑整页 → 补周次 |
| 时间重叠 | 与另一门课节次冲突 | 展示冲突的两门课；用户可改节次或删除其一 |
| 缺少教室 | 地点为空 | 点行 → 编辑整页 → 补地点 |

**编辑**：点任一行 → 打开整页课程编辑（复用 `showCourseFormSheet`），字段 = 课程名 / 教师 / 地点 / 星期 / 节次 / 周次 / 颜色（颜色自动派生，可改）。保存后回到清单，问题角标实时消失。

**底部**：`+ 添加课程`（次要，空白行进入编辑） / `下一步：提交审核`（主按钮）。
- 若仍有「周次待确认」的课程 → 主按钮可点，但下一步 Step 3 顶部会再提醒一次（不硬拦，因为审核员也会核对）。

### 4.3 Step 3 · 提交审核

```
┌ 归属与来源 ────────────────────────┐
│ 2026-2027 第1学期                   │
│ 智能工程学院 · 电气工程及其自动化   │
│ 25电气1班 · v1                     │
│ 来源  从本机课程表导入              │
│       25电气1班 · 28 门            │
└────────────────────────────────────┘

┌ 上传者名称 * ─────────────────────┐
│ [ 张同学                        ]  │
│ 将展示在班级课表的版本卡片上，最多 16 字。│
│ 请用昵称，不要填写真实姓名、学号或手机号。│
└────────────────────────────────────┘

┌ 隐私自检 ──────────────────  通过 ✓ ┐
│ ✓ 上传者名称不含学号、真实姓名、手机号  │
│ ✓ 课程内容不含成绩、作业与通知内容      │
│ ✓ 账号身份不随课表公开，仅以你填写的名称展示 │
└────────────────────────────────────┘

补充说明（选填）
┌────────────────────────────────────┐
│ 例如：第 8 周起班级换教室，已按最新通知更新 │
└────────────────────────────────────┘

☐ 我确认该课表为班级公开信息，不包含个人隐私，
  并同意平台在审核与展示中以我填写的「上传者名称」展示贡献者。

[      提交审核      ]
```

**交互：**
- **上传者名称**（新增必填字段）：
  - 输入框，占位符「填一个同学都认得的名字，例如：张同学」。
  - 限制：**最多 16 字**；不得包含学号（连续 6+ 位数字）、手机号（11 位数字）、真实姓名（无法自动判定，靠提示与审核拦截）。
  - 用途：这个名字会显示在班级课表的版本卡上（小字三要素之一），让同学知道「这份表是谁传的」，建立信任。
  - **默认建议**：可带出本机已有课表的名称（`CourseTable.name`）作为预填，减少输入成本，用户可改。
  - 服务端只存这一个显示名 + 账号标识，**账号身份不随课表公开**。
  - 未填 → 主按钮禁用 + 提示「请填写上传者名称」。
- 隐私自检是**客户端本地检查**（扫描课程名 / 教师 / 地点 / 上传者名称里是否含手机号串、疑似学号串）+ 固定三条声明。有命中时该项变红并给出「检测到疑似手机号，请修改后再提交」。
- 同意勾选**未勾选时主按钮禁用**（按钮呈灰态，提示「请先勾选确认」）。
- 点提交 → 主按钮 loading「正在提交…」→ 成功 → 跳「我的上传」页（定位到该条）+ SnackBar「已提交审核，通常 1 个工作日内完成」。
- 提交失败 → 按钮恢复 + SnackBar「提交失败：网络异常，已为你保留填写内容」+ **停留在 Step 3**，内容不丢。

**版本号**：同一上传者 + 同一班级 + 同来源再次提交 → 自动升版本；界面在 Step 3 显示「v2（将替代 v1）」。

## 6. 后台审核端交互（运营后台）

### 6.2 详情页（审核核心）

**左侧栏**：班级归属（学年学期 / 学院 / 专业 / 班级）+ 来源与上传者（来源两种之一 + 上传者名称 + 提交时间 + 版本）+ **隐私自检**（学号 / 姓名 / 手机号 三项，各带「未检出」绿标签）。

**右侧主区**：
1. **审核决定卡**：状态「待审核」+ 按钮组 `通过并发布`（主）/ `驳回`（次）/ `下架已发布课表`（禁用态）+ 说明「通过后立即进入发布队列，由 worker 异步发布；发布完成前客户端检索不到该课表。驳回会保留审核记录，提交者可按意见修正后重新上传。」+ 审核人 / 审核时间（待审核时显示「—」）。
2. **并排比对表**：左「上传内容」右「教务基准」，列 = 课程 / 教师 / 地点 / 周次 / 节次。
   - 一致行 = 绿条 + 浅绿底（`--ok-weak`）；差异行 = 浅红底（`--warn-weak`）+ 左红条，**具体差异字段标红**（如周次 `3-15周（单周）` vs `3-15周（双周）`、节次 `周三 5-6节` vs `周三 1-2节`）。
   - 图例：红条 + 浅红底 = 与基准不一致；绿条 + 浅绿底 = 课程、教师、地点、周次、节次逐字段一致。
   - 右上角「共 28 门 · 展示前 9 门」（超量折叠）。
3. **汇总条**（紫底）：「共 28 门，匹配 26 门，差异 2 门（周次不一致 1、时间冲突 1）」+ 逐条差异明细。
4. **驳回意见卡**（默认展开在下方，或点「驳回」后展开）：驳回原因下拉（必填）+ 审核意见 textarea（**最多 500 字**，实时显示 `0 / 500`）+ 「确认驳回」按钮。提示「驳回原因与意见写入审核留痕，并随列表展示反馈给提交者；不会在客户端展示。」
5. **操作留痕卡**：只读时间线（上传提交 / 一致性比对 / 隐私自检通过 / 管理员打开详情 / 审核动作），说明「审核动作、审核人与时间均写入审计日志，不可编辑。」

**通过后的链路**：`PATCH /admin/timetables/{id}/status {status: 'approved'}` → 写 `audit_logs` → 入队 `timetable_publish_jobs(action='publish')` → 返回 `{"ok":true,"jobId":4821,"queued":true}` → 前端 toast「已通过并进入发布队列（任务 #4821）」+ 状态刷新为「已通过 · 发布中」。

**驳回链路**：必须选原因 → `PATCH ... {status:'rejected', reason:'mismatch_with_campus', reviewNote:'...'}` → toast「已驳回，提交者可在客户端看到原因」。

**下架链路**：`status:'removed'` → 二次确认弹窗（「下架后客户端检索不再展示该课表，上传记录与审核留痕保留。确认下架？」）→ toast「已下架」。

### 6.3 队列与重试

- 「发布队列」提示条中的「失败 1」可点开 → 展开失败任务列表。

```
  │              │                  │◄── PATCH status ─────┼───────────│            │
  │              │                  │ 写 audit_logs          │            │            │
  │              │                  │ enqueue publish job ──►│            │            │
  │              │                  │                       │ 发布索引    │            │
  │              │                  │◄── job done ──────────┤            │            │
  │  状态推送     │                  │                      │            │            │
  │  [已通过·    │                  │                      │            │            │
  │   发布中]    │◄── uploads/mine ─│                      │            │            │
  │              │ (resumed 静默刷新)│                     │            │            │
  │              │                  │                      │            │  检索课表   │
  │              │                  │◄── POST search ───────┼───────────┼───────────►│
  │              │                  │ 仅返回 status=approved 且 published=1        │
  │              │                  │                      │            │            │
  │              │◄───────────────────────────────────────────────────────────────│
  │              │  详情 → 导入确认 → 覆盖或新增本机同名班级课表                      │
  │              │  → 切换到该课表 → 课表页生效（kindImported，不被「我的教务」覆盖）  │
```

**关键时序约束：**
1. `approved` 与「客户端可检索」之间**隔着一次异步发布**，两端都要如实展示这个中间态。
2. 客户端检索**永远只查已发布**，不存在「审核员点了通过但同学立刻就看到未发布内容」的风险。
3. 客户端**不轮询审核详情**，只轮询「我的上传」列表；状态变化通过列表比对推送。
4. **覆盖发生在客户端**，服务端不做「导入」；服务端只负责发布与检索可见性。

## 8. 边界与异常交互

| 场景 | 交互表现 |
|---|---|
| 同一班级多人上传 | 详情页并列展示全部份数（等宽版本卡），各自带上传者名称；按一致度排序，不设唯一正确版 |
| 同一上传者重复上传 | 自动升版本，Step 3 显示「v2（将替代 v1）」；旧版在客户端隐藏但服务端留档 |
| 上传内容与教务完全对不上 | 一致性 < 85% → 后台标红「8 门待核对」；默认要求逐条核对后才可通过（不自动通过） |
| 课表已过学期 | 后台批量下架；客户端默认只显示当前学年学期的班级课表 |
| 审核积压 | 来源只有两种且都是本机真实课表，审核员只需比对结构与一致性；页脚如实写「通常 1 个工作日内完成」 |
| 用户上传错班级 | 归属四段必填 + 与教务基准比对（班级课表一比对即知错）；归属有误 → 驳回原因 `wrong_class` |
| 用户上传含个人信息 | 客户端提交前自检 + 服务端扫描 + 人工审核三重把关；命中 → 驳回原因 `personal_info` |
| 上传者名称填了学号/手机号 | 客户端实时拦截（6 位以上连续数字 / 11 位手机号）；服务端同样校验并返回 `invalid_uploader_name` |
| 导入时网络中断 | sheet 停留，按钮恢复，文案「导入失败，请重试」；不产生半截数据 |
| 覆盖时本机有 `kindOwn` 课表 | 不覆盖，改为新增一份 `kindImported` 课表，提示「你的个人课表不会被替换，已为你新增一份」 |
| 课表切换 | 导入后自动切到该课表，并触发 `WidgetSyncService.syncTodayCourses()` + `CourseReminderService.rescheduleAll()`（与既有切表逻辑一致） |
| 检索为空 | 不显示「暂无数据」了事，必须给出「上传班级课表」的出口 |

## 9. 关键 API 与交互的对应关系

| 交互动作 | 请求 | 成功反馈 | 失败反馈 |
|---|---|---|---|
| 检索课表 | `POST /api/v1/timetables/search` | 班级聚合列表 + 份数 | 顶部错误条 + 保留缓存 + 重试 |
| 班级详情 | `GET /api/v1/timetables/class/{class_key}` | 多份课表 + 课程明细 + 上传者名称 | 整页错误态 + 重试 |
| 提交上传 | `POST /api/v1/timetables/uploads` | 跳「我的上传」+ SnackBar | 停留 Step 3 + 保留内容 + SnackBar |
| 我的上传列表 | `GET /api/v1/timetables/uploads/mine` | 状态分组列表 | 错误条 + 重试（保留上次结果） |
| 撤销上传 | `DELETE /api/v1/timetables/uploads/{id}` | 行消失 + SnackBar | 二次确认后失败 → 保留行 + SnackBar |
| 驳回后重提 | `POST /api/v1/timetables/uploads/{id}/resubmit` | 版本升 v(n+1) | 停留在 Step 3 |
| 收藏 | `POST /api/v1/timetables/favorites/{class_key}` | 按钮变「已收藏」 | 按钮回滚 + SnackBar |
| 审核通过 | `PATCH /admin/timetables/{id}/status` | toast + 状态刷新 | 保留输入 + toast 报错 |
| 队列重试 | `POST /admin/timetables/queue/{job_id}/retry` | toast「已重新入队」 | 卡片保留失败态 + toast |
| 教务基准（审核时按需拉取） | `POST /api/v1/course/class/schedule` | 并排比对表 | 提示「无法拉取教务基准，请稍后重试」+ 保留上传内容比对 |
