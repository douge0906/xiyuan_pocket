# 服务端新增实现提示词 · 锡院在线课表（班级课表上传与导入）

> **目标**：在 `xiyuan_control` 服务内实现「锡院在线课表」的服务端能力 —— 上传、审核、异步发布、检索、收藏。
> **范围**：仅服务端。Flutter 客户端与 `xiyuan_toolbox` 不在本次改动范围。
> **对应设计版本**：v1.2（2026-11-25）　　**配套设计稿与说明**：`设计方案_班级课表上传与导入_2026-11-24.md`、`交互逻辑说明_班级课表上传与导入_2026-11-24.md`

---

## 1. 业务硬约束

- 上传来源**只有两种**：`local_table`（从本机课程表导入）、`local_file`（从本机导出的文件导入）。其它值一律 400。
- 服务端**只接收结构化课程行**，不收 PDF / 图片二进制 → **不需要附件表、不需要对象存储链路**。
- 上传必须带**上传者名称**（自填，1–16 字）。它是唯一对外可见的贡献者标识；账号标识仅用于归属与撤销。
- 检索与详情**只返回已发布**的课表：`status='approved' AND published=1`。
- 审核通过（`approved`）与「客户端可检索」之间隔着一次**异步发布**，这是刻意的两段式，不合并。
- 服务端**没有「导入」接口**。客户端「导入到我的课表」的覆盖动作完全发生在本地，服务端不参与。

| 位置 | 复用什么 |
|---|---|
| `C:/build_ws/xiyuan_control/app/api.py` | 客户端端点路由写法、pydantic 请求体模型、`fail(status, code, message)` 错误信封、限流口径 |
| `C:/build_ws/xiyuan_control/app/admin.py` | 后台端点、`require_admin(request, authorization)`、`audit(conn, action, detail)`、列表 GET / 详情 GET / 状态 PATCH / 队列 GET 的形状 |
| `C:/build_ws/xiyuan_control/app/db.py` | `CREATE TABLE IF NOT EXISTS` 建表、`_ensure_column(conn, table, column, ddl)` 增量迁移、`init()` |
| `C:/build_ws/xiyuan_control/app/resource_jobs.py` + `resource_worker.py` | outbox 队列范式（入队复用同 id+action 的 pending/running 行；退避 `min(300, 10*2**(attempts-1))` 秒；`_MAX_ATTEMPTS = 6`；超限置 `failed` 并写 `last_error`） |
| `C:/build_ws/xiyuan_control/app/main.py` | `include_router` 装配顺序、错误信封输出、`X-Request-Id` 响应头 |

关键细节：

- **错误信封**（control 侧，与 toolbox 的 `{"detail": "..."}` 不同）：
  ```python
  def fail(status: int, code: str, message: str): ...   # → {"error": {"code": code, "message": message}, "request_id": ...}
  # main.py 统一输出；未捕获异常 → code "server_error" / message "服务器内部错误"
  ```
- **后台鉴权**（`admin.py:30-37`，在 admin.py 里，不在 security.py）：`Authorization: Bearer <cfg.admin_key>`，`secrets.compare_digest` 比对；失败 → 401 `{"code":"admin_unauthorized","message":"管理员令牌无效"}`。
- **审计**：`audit(conn, action, detail="")` → `INSERT INTO audit_logs(action, actor='admin', detail, created_at)`。
- **列表排序**（照抄 `GET /admin/resources`）：`ORDER BY CASE status WHEN 'pending' THEN 0 ELSE 1 END, id DESC LIMIT 500`。
- **客户端鉴权**：沿用 control 侧既有客户端端点那套（与 `/api/v1/resources`、`/api/v1/resource-uploads` 一致）。**不要**用 `X-Admin-Key`，**不要**用 toolbox 的 `_auth_required`。

## 3. 数据表（新建 4 张）

放进 `xiyuan_control/app/db.py` 的 `SCHEMA` 字符串，`init()` 里确保被调用。

```sql
-- 一份上传 = 一个班级下的一份课表（= 一个版本）
CREATE TABLE IF NOT EXISTS timetable_uploads (
    id              INTEGER PRIMARY KEY AUTOINCREMENT,
    device_id       INTEGER NOT NULL,
    contributor     TEXT NOT NULL DEFAULT '',   -- 账号标识（仅用于归属与撤销，不对外展示）
    uploader_name   TEXT NOT NULL DEFAULT '',   -- 上传者名称（对外展示，≤16 字）
    xnm             TEXT NOT NULL,              -- 学年码 2026
    xqm             TEXT NOT NULL,              -- 学期码 3/12/16
    jgmc            TEXT NOT NULL,              -- 学院
    zymc            TEXT NOT NULL,              -- 专业
    bj              TEXT NOT NULL,              -- 班级
    njdm_id         TEXT NOT NULL DEFAULT '',   -- 年级码
    source          TEXT NOT NULL,              -- local_table / local_file
    version         INTEGER NOT NULL DEFAULT 1,-- 同 contributor 同班级同来源内递增
    course_count    INTEGER NOT NULL DEFAULT 0,
    diff_matched    INTEGER NOT NULL DEFAULT 0,-- 与基准一致的课程数（无基准时 0）
    diff_total      INTEGER NOT NULL DEFAULT 0,-- 参与比对的课程数（无基准时 0）
    note            TEXT NOT NULL DEFAULT '',
    status          TEXT NOT NULL DEFAULT 'pending', -- pending/approved/rejected/removed
    published       INTEGER NOT NULL DEFAULT 0, -- 1 = 已发布（客户端可见的必要条件）
    review_note     TEXT NOT NULL DEFAULT '',
    review_reason   TEXT NOT NULL DEFAULT '',
    created_at      TEXT NOT NULL,
    reviewed_at     TEXT,
    published_at    TEXT
);
CREATE INDEX IF NOT EXISTS idx_timetable_uploads_status ON timetable_uploads(status, id);
CREATE INDEX IF NOT EXISTS idx_timetable_uploads_class  ON timetable_uploads(xnm, xqm, jgmc, zymc, bj);
CREATE INDEX IF NOT EXISTS idx_timetable_uploads_owner  ON timetable_uploads(device_id, contributor, xnm, xqm, jgmc, zymc, bj, source);

-- 课程明细（一行一门课）
CREATE TABLE IF NOT EXISTS timetable_courses (
    id           INTEGER PRIMARY KEY AUTOINCREMENT,
    upload_id    INTEGER NOT NULL,
    name         TEXT NOT NULL,
    teacher      TEXT NOT NULL DEFAULT '',
    classroom    TEXT NOT NULL DEFAULT '',
    weekday      INTEGER NOT NULL,             -- 1..7
    start_slot   INTEGER NOT NULL,
    end_slot     INTEGER NOT NULL,
    weeks        TEXT NOT NULL DEFAULT '',
    FOREIGN KEY (upload_id) REFERENCES timetable_uploads(id) ON DELETE CASCADE
);
CREATE INDEX IF NOT EXISTS idx_timetable_courses_upload ON timetable_courses(upload_id);

-- 收藏（收藏的是班级引用，不是课表副本）
CREATE TABLE IF NOT EXISTS timetable_favorites (
    device_id  INTEGER NOT NULL,
    class_key  TEXT NOT NULL,
    created_at TEXT NOT NULL,
    PRIMARY KEY (device_id, class_key)
);

-- 发布队列（outbox）
CREATE TABLE IF NOT EXISTS timetable_publish_jobs (
    id          INTEGER PRIMARY KEY AUTOINCREMENT,
    upload_id   INTEGER NOT NULL,
    action      TEXT NOT NULL,                  -- publish / unpublish
    status      TEXT NOT NULL DEFAULT 'pending',-- pending/running/done/failed
    attempts    INTEGER NOT NULL DEFAULT 0,
    last_error  TEXT NOT NULL DEFAULT '',
    created_at  TEXT NOT NULL,
    updated_at  TEXT NOT NULL,
    next_run_at TEXT NOT NULL
);
CREATE INDEX IF NOT EXISTS idx_timetable_publish_jobs_status ON timetable_publish_jobs(status, next_run_at);
```

**不复用 `resource_publish_jobs`**：`resource_jobs.enqueue` 的 action 白名单硬编码 `("publish","delete")`，worker 分支硬编码 `_publish_resource_files` / `_delete_resource_objects`。课表没有文件对象，发布语义不同。**新建平行表 + 复用同一套 worker 范式**是最小改动。

**不建附件表**：文件在客户端就被解析成结构化课程了，服务端只收结构化行。

### `class_key`（客户端与服务端必须一致）

```
class_key = f"{xnm}-{xqm}|{jgmc}|{zymc}|{bj}"
```

用 `|` 分隔是因为学院/专业名里可能含 `-`。**同名即同键**，不做模糊匹配。

## 4. 客户端可见端点（8 个）

前缀 `/api/v1/...`，鉴权沿用 control 侧客户端端点既有方式。

### 4.1 `POST /api/v1/timetables/search`

按四段 + 关键字检索**已发布**课表，返回**班级聚合列表**。

请求体：
```json
{"xnm":"2026","xqm":"3","jgmc":"","zymc":"","bj":"","keyword":"25安工"}
```

- `xnm`、`xqm` 必填（`xqm` ∈ 3/12/16）；`jgmc/zymc/bj/keyword` 可空（空 = 全部）。
- 四个下拉的**候选项**由客户端从本接口返回结果里聚合得出 → 本接口必须返回足够信息让客户端推出「有哪些学院/专业/班级」。

响应：
```json
{
  "success": true,
  "data": {
    "xnm": "2026", "xqm": "3", "total": 128, "count": 128,
    "classes": [
      {
        "class_key": "2026-3|智能工程学院|电气工程及其自动化|25电气1班",
        "bj": "25电气1班",
        "zymc": "电气工程及其自动化",
        "jgmc": "智能工程学院",
        "njdm_id": "2025",
        "timetable_count": 2,
        "course_count": 28,
        "latest_uploaded_at": "2026-11-25T09:12:00Z",
        "latest_uploader_name": "张同学",
        "consistency": {"matched": 26, "total": 28}
      }
    ]
  }
}
```

**可见性闸门（硬要求）**：`WHERE u.status = 'approved' AND u.published = 1` —— `pending` / `rejected` / `removed` / `approved 但未发布` 一律对他人不可见。

### 4.2 `GET /api/v1/timetables/class/{class_key}`

取某班级下**全部已发布课表**（多份并列）+ 课程明细 + 上传者名称 + 一致度。

```json
{
  "success": true,
  "data": {
    "class_key": "2026-3|智能工程学院|电气工程及其自动化|25电气1班",
    "xnm": "2026", "xqm": "3",
    "jgmc": "智能工程学院", "zymc": "电气工程及其自动化", "bj": "25电气1班",
    "njdm_id": "2025",
    "timetable_count": 2,
    "timetables": [
      {
        "id": 1024, "version": 2,
        "uploader_name": "张同学", "source": "local_table",
        "course_count": 28,
        "created_at": "2026-11-25T09:12:00Z",
        "published_at": "2026-11-25T10:02:00Z",
        "consistency": {"matched": 26, "total": 28},
        "note": "第 8 周起换教室",
        "courses": [
          {"name":"大学物理实验Ⅱ","teacher":"朱弘桢","classroom":"C2",
           "weekday":3,"start_slot":3,"end_slot":4,"weeks":"1-16周"}
        ]
      }
    ]
  }
}
```

- 版本按 `created_at` **倒序**。
- 课程明细字段名统一 **snake_case 7 键**：`name / teacher / classroom / weekday / start_slot / end_slot / weeks`（与 `xiyuan_toolbox/server/class_timetable.py` 的班级课表同构；**不要**用 PDF 解析器那套 camelCase）。
- `weeks` 原样存文本（`"1-16周"`、`"1-8周,10-16周"`）。

### 4.3 `POST /api/v1/timetables/uploads`

提交上传。服务端固定 `status='pending'`、`published=0`。

请求体（**注意：请求体是 camelCase，响应体是 snake_case**）：
```json
{
  "xnm": "2026", "xqm": "3",
  "jgmc": "智能工程学院", "zymc": "电气工程及其自动化", "bj": "25电气1班",
  "njdmId": "2025",
  "source": "local_table",
  "uploaderName": "张同学",
  "courses": [
    {"name":"大学物理实验Ⅱ","teacher":"朱弘桢","classroom":"C2",
     "weekday":3,"startSlot":3,"endSlot":4,"weeks":"1-16周"}
  ],
  "note": "第 8 周起换教室",
  "campusBaseline": null
}
```

字段约束：

| 字段 | 约束 | 违规错误 |
|---|---|---|
| `xnm` / `xqm` | 必填非空 | 400 `invalid_term` |
| `jgmc` / `zymc` / `bj` | 必填，去首尾空格后仍非空 | 400 `invalid_class` |
| `source` | 枚举，仅 `local_table` / `local_file` | 400 `invalid_source` |
| `uploaderName` | 必填；去空格后 1–16 字；**不得含 6 位以上连续数字**（疑似学号）、**不得含 11 位手机号** | 400 `invalid_uploader_name`（命中疑似学号/手机号**直接拒绝**，不静默替换、不打码） |
| `courses` | 1–200 条；`name` 非空；`weekday` 1..7；`start_slot` ≥ 1；`end_slot` ≥ `start_slot` | 400 `invalid_courses` |
| `weeks` | 文本，原样存 | 解析失败按「每周都上」处理（客户端已解析，服务端只存文本） |
| `note` | 可选，≤500 字 | 超长截断或 400，二选一，交付说明里写明选了哪种 |
| `campusBaseline` | 可选数组，结构同 `courses`，用于算一致度 | 400 `invalid_courses` |

- **版本号**：同一 `device_id + contributor + (xnm,xqm,jgmc,zymc,bj) + source` 下 `version = max(version)+1`，否则为 1。
- **不覆盖旧记录**：同班多份并存是产品要求，旧版本保留在服务端（客户端只展示最新）。
- **一致度**：带 `campusBaseline` 时，按匹配键 `(课程名归一化, weekday, start_slot, end_slot)` 比对，命中且 `weeks/teacher/classroom` 全同 → `matched += 1`，写入 `diff_matched` / `diff_total`；无基准时两者都写 0，客户端显示「未比对」。
- **课程名归一化**：去空白、全角转半角、去掉括注内容后再比较。

响应：
```json
{"success": true, "data": {"id": 1024, "version": 1, "status": "pending", "created_at": "2026-11-25T09:12:00Z"}}
```

### 4.4 `GET /api/v1/timetables/uploads/mine`

当前账号的上传列表（**含非发布状态**，这是与 4.1 的关键区别）。

```json
{
  "success": true,
  "data": {
    "count": 5,
    "uploads": [
      {"id":1024,"version":1,"xnm":"2026","xqm":"3",
       "jgmc":"智能工程学院","zymc":"电气工程及其自动化","bj":"25电气1班",
       "source":"local_table","uploader_name":"张同学",
       "course_count":28,"status":"pending","published":0,
       "created_at":"...","reviewed_at":null,"review_reason":"","review_note":""}
    ]
  }
}
```

状态语义（客户端据此区分两个子态，务必一致）：

| status | published | 客户端文案 |
|---|---|---|
| `pending` | 0 | 待审核 |
| `approved` | 0 | 审核通过 · 发布中 |
| `approved` | 1 | 已发布 |
| `rejected` | 0 | 已驳回（带 `review_reason` + `review_note`） |
| `removed` | 0 | 已下架 |

### 4.5 `DELETE /api/v1/timetables/uploads/{id}`

撤销自己处于 `pending` 的上传。非 pending → 400 `cannot_revoke`（「只有待审核的上传可以撤销」）；非本人 → 404。撤销时一并删除该上传的课程明细。

### 4.6 `POST /api/v1/timetables/uploads/{id}/resubmit`

驳回后修改重提，body 同 4.3（`courses` 等由客户端重新给出）。

- 只有 `rejected` 允许重提；其它状态 → 400 `invalid_status`。
- **不新建行**：在同一行上更新 `courses`、`uploader_name`、`note`、`version = version + 1`、`status='pending'`、`published=0`、`review_note=''`、`review_reason=''`、`reviewed_at=NULL`；旧课程明细先清空再写入。

## 5. 后台审核端点（6 个）

前缀 `/admin/...`，全部走 `require_admin(request, authorization)`。

### 5.1 `GET /admin/timetables?status=&xnm=&xqm=&jgmc=&keyword=`

- `status` 白名单 `pending/approved/rejected/removed`，非法 → `fail(400, "invalid_status", "状态只能是 pending / approved / rejected / removed")`。
- `xnm` / `xqm` / `jgmc` / `keyword`（匹配班级名/学院/专业）皆可选。
- 排序：`ORDER BY CASE status WHEN 'pending' THEN 0 ELSE 1 END, id DESC LIMIT 500`。
- 每行返回：班级（`bj` + `zymc`/`jgmc` 副行）、`xnm`/`xqm`、`uploader_name`、`version`、`course_count`、`diff_matched`/`diff_total`、`created_at`、`status`、`published`。

### 5.2 `GET /admin/timetables/{id}`

审核详情：归属四段 + 来源 + 上传者名称 + 课程明细 + **与教务基准的比对结果**。

```json
{"success": true, "data": {
  "upload": { "...同 mine 的单条字段..." },
  "courses": [ "...明细..." ],
  "campus_baseline": [ "...随上传附带的基准，可为 null..." ],
  "diff": {
    "total": 28, "matched": 26,
    "items": [
      {"name":"大学物理实验Ⅱ","status":"same",
       "uploaded":{"teacher":"朱弘桢","classroom":"C2","weekday":3,"start_slot":3,"end_slot":4,"weeks":"1-16周"},
       "baseline":{"teacher":"朱弘桢","classroom":"C2","weekday":3,"start_slot":3,"end_slot":4,"weeks":"1-16周"}},
      {"name":"数字电子技术","status":"diff",
       "uploaded":{"weekday":3,"start_slot":9,"end_slot":10,"weeks":"3-15周（单周）"},
       "baseline":{"weekday":3,"start_slot":7,"end_slot":8,"weeks":"3-15周（双周）"}},
      {"name":"形势与政策","status":"missing"},
      {"name":"军事理论","status":"extra"}
    ]}}}
```

`status` 四取值：`same`（全字段一致）/ `diff`（匹配键相同但 weeks/teacher/classroom 有差异）/ `extra`（上传有、教务无）/ `missing`（教务必、上传无）。**差异要标到字段级** → `diff` 里必须给出两侧字段值。

### 5.3 `PATCH /admin/timetables/{id}/status`

body：`{"status": "approved" | "rejected" | "removed", "reviewNote": "...", "reason": "..."}`

- `status` 只允许 `approved/rejected/removed`，其它 → `fail(400, "invalid_status", ...)`。
- `reviewNote`：`str(body.get("reviewNote") or "").strip()[:500]`（截断到 500 字，不报错）。
- `reason`：只在 `rejected` 时必填，取值必须是下列之一，否则 `fail(400, "invalid_reason", ...)`：
  `mismatch_with_campus`（与教务基准差异过大）/ `incomplete_info`（课程信息不完整）/ `duplicate`（与已有课表重复）/ `personal_info`（疑似含个人信息）/ `wrong_class`（归属班级有误）/ `other`。
- 副作用：
  - `approved` → 写 `status='approved'`、`reviewed_at`；**入队 publish job**（`action='publish'`）；**不直接置 `published=1`**。
  - `rejected` → 写 `status='rejected'`、`review_reason`、`review_note`、`reviewed_at`；`published` 保持 0。
  - `removed` → 写 `status='removed'`、`reviewed_at`；若原先 `published=1`，入队 `action='unpublish'` job 把 `published` 置 0。
- 每次写 `audit_logs`（`audit(conn, action, detail)`），detail 带 `upload_id`、新状态、reason、reviewNote。

响应：
```json
{"success": true, "data": {"id": 1024, "status": "approved", "published": false, "job_id": 4821, "queued": true}}
```

### 5.4 `GET /admin/timetables/queue`

发布队列状态：`pending/running/done/failed` 计数 + 最近任务列表（任务号、upload_id、班级名、action、status、attempts、last_error、next_run_at）。返回形状照抄 `GET /admin/resources/queue`。

### 5.5 `POST /admin/timetables/queue/{job_id}/retry`

手动重试失败任务：置回 `pending`、`attempts` 归零、`next_run_at` 置当前时间、`last_error` 保留（供排查）。非 `failed` → `fail(400, "invalid_job_status", ...)`。

### 5.6 `GET /admin/timetables/classes?xnm=&xqm=&keyword=`

班级维度聚合：某班级下**全部**上传记录（跨上传者，含未发布），用于查重与「同班级其它上传」列表。返回每个 `class_key` 下的上传条数与版本列表。

## 6. 异步发布队列（outbox）

**新建** `xiyuan_control/app/timetable_jobs.py` + `timetable_worker.py`；**不改** `resource_jobs.py` / `resource_worker.py`（教材资源那条链路独立运行）。

### 6.1 入队

```python
def enqueue(conn, upload_id: int, action: str) -> int:
    # action 白名单 ("publish", "unpublish")，否则 raise ValueError("invalid publish action")
    # 同 upload_id + action 已有 pending/running 的 job → 复用该行（不新建）
    # 否则 INSERT 一行 pending 的 job，next_run_at = now
```

### 6.2 worker 行为

- 轮询 `status='pending' AND next_run_at <= now` 的任务，取一条置 `running` 处理。
- `action='publish'`：
  1. 校验该 upload 仍是 `status='approved'`（否则跳过并置 done）。
  2. **发布 = 把 `timetable_uploads.published` 置 1、`published_at` 置当前时间**（课表没有文件对象，发布就是把可见性闸门打开；将来要加索引表，在这里写索引 upsert）。
  3. 置 job `done`。
- `action='unpublish'`：`published` 置 0，置 job `done`。
- **失败处理**：捕获异常 → `attempts += 1`；`attempts < 6` → 置回 `pending`，`next_run_at = now + min(300, 10 * 2 ** (attempts - 1))` 秒，`last_error` 记异常摘要；`attempts >= 6` → 置 `failed`。
- worker 能独立启动（照抄 `resource_worker.py` 启动方式），且**可重复执行、幂等**。

### 6.3 失败对可见性的影响

发布失败**不影响审核状态**：课表仍是「已通过但未发布」，客户端检索不到；后台能看到失败任务并能重试（5.5）。**不要**因为发布失败把 `status` 改回去。

## 7. 鉴权与隐私

- 客户端端点：沿用 control 侧客户端端点既有鉴权方式（与 `/api/v1/resources`、`/api/v1/resource-uploads` 一致）。不用 `X-Admin-Key`，不用 toolbox 的 `_auth_required`。
- 后台端点：`require_admin(request, authorization)`，即 `Authorization: Bearer <cfg.admin_key>`；失败 401 `{"code":"admin_unauthorized","message":"管理员令牌无效"}`。
- **`uploader_name` 是唯一对外可见的贡献者标识**（1–16 字，用户自填）。
- 平台**只保留学号哈希前缀**用于识别重复提交（如 `哈希 7f3a…c21b`），**不存学号明文、不存真实姓名**。`contributor` 仅供内部归属与撤销，**不得出现在任何客户端可见响应里**；后台列表与详情可返回 `uploader_name`，不得返回学号明文。
- 上传的 `courses` 中若检测到疑似手机号（11 位连续数字）或疑似学号串（6 位以上连续数字），**入库置空该字段**并在该上传上记 `personal_info` 标记供审核员判定，同时写入 `audit_logs`。

## 8. 错误码总表

| HTTP | code | 何时 |
|---|---|---|
| 400 | `invalid_term` | 学年/学期缺失 |
| 400 | `invalid_class` | 学院/专业/班级缺失 |
| 400 | `invalid_source` | source 不在 {local_table, local_file} |
| 400 | `invalid_uploader_name` | 名称为空、超 16 字、含疑似学号或手机号 |
| 400 | `invalid_courses` | 课程条数越界或字段非法 |
| 400 | `invalid_status` | 状态不在白名单 |
| 400 | `invalid_reason` | 驳回原因码不在白名单 |
| 400 | `invalid_job_status` | 重试了非 failed 的任务 |
| 400 | `cannot_revoke` | 撤销了非 pending 的上传 |
| 401 | `admin_unauthorized` | 后台令牌无效 |
| 404 | `not_found` | id 不存在或不属于当前账号 |
| 500 | `server_error` | 未捕获异常（由 main.py 统一兜底） |

错误文案用中文、克制、面向终端用户（参考既有 `fail(400,"invalid_status",...)` 的语气）。

## 9. 迁移与上线

1. **建表**：4 张表用 `CREATE TABLE IF NOT EXISTS` 加进 `db.py` 的 `SCHEMA`，`init()` 里确保被调用 —— 新装与老库都能跑，不需要手工迁移脚本。
2. **不改动既有表**：`resource_uploads` 等教材资源表一个字都不要动。
3. **路由注册**：新 router 在 `main.py` 的 `include_router` 里注册，必须在启动时被 include。
4. **worker 启动**：与 `resource_worker.py` 一致，能单独起、单独停。
5. **限流**：客户端端点沿用 control 侧既有客户端端点的限流口径，不另设一套。

## 10. 验收清单（交付时逐条真跑并贴结果）

**基础**
- [ ] 全新库启动 → 4 张表自动建好。
- [ ] 已有库启动 → 无报错；重复执行 `init()` 不报错（幂等）。
- [ ] `GET /admin` 正常打开，既有资源审核功能不受影响（回归）。

**上传**
- [ ] 提交合法上传 → 返回 `id`，`status='pending'`，`published=0`。
- [ ] `source='pdf'` → 400 `invalid_source`。
- [ ] `uploaderName` 为空 / 17 字 / 含 11 位手机号 / 含 8 位数字串 → 400 `invalid_uploader_name`。
- [ ] `courses` 0 条 / 201 条 → 400 `invalid_courses`。
- [ ] 同一账号同班同来源再提交 → `version` 变 2，**旧行仍在**。
- [ ] 不同账号同班提交 → 两行并存，各自 `version=1`。

**可见性闸门**
- [ ] `search` 对 `pending` 的课表查不到。
- [ ] 审核 `approved` 后**立刻**搜索 → 查不到（尚未发布）。
- [ ] worker 发布完成后 → 查得到。
- [ ] `rejected` / `removed` → 查不到。

**审核与发布**
- [ ] `GET /admin/timetables?status=` 四种状态过滤正确；非法 status → 400 `invalid_status`。
- [ ] `PATCH .../status {approved}` → 写 `audit_logs`、返回 `job_id`、生成一条 `pending` 的 publish job。
- [ ] 驳回不带 reason → 400 `invalid_reason`；带合法 reason → `status='rejected'`、`review_reason` 落库。
- [ ] `reviewNote` 传 600 字 → 入库截到 500 字。
- [ ] `DELETE` 一个 `approved` 的上传 → 400 `cannot_revoke`。
- [ ] `resubmit` 一个 `rejected` 的上传 → 同 id、`version+1`、`status='pending'`、明细已替换。
- [ ] 模拟发布异常 → job 退避重试；6 次后 `failed` + `last_error` 有值；`retry` 能重新入队。
- [ ] `removed` 一个已发布的课表 → 生成 `unpublish` job → 执行后 `published=0` → 客户端搜索查不到。

**收藏**
- [ ] `POST` 收藏 → `GET /favorites` 有该 `class_key`；`DELETE` 后消失。
- [ ] 同一班级上传新版本 → 收藏项仍指向该班级（不产生副本）。

**一致度**
- [ ] 带 `campusBaseline` 上传 → `diff_matched/diff_total` 正确；详情 `diff.items` 四种 `status` 都能出现。
- [ ] 不带 `campusBaseline` → 两值为 0，详情 `campus_baseline` 为 `null`。

**收尾**
- [ ] 全部新端点的错误响应都是 `{"error":{"code","message"},"request_id"}` 形状，没有 toolbox 那种 `{"detail": "..."}`。
- [ ] 没有任何接口把 `contributor`、学号明文、真实姓名返回给客户端。
- [ ] 给出每个端点的 curl 示例（可直接粘贴执行），并说明改动文件清单与迁移幂等性。
